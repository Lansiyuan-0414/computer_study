# 二叉树与递归
## step1.什么是树
1. 树是一种有层级关系，可以分叉但不能成环的数据结构，通常由一个根节点和若干子树构成，一般通过结构体定义二叉树节点
2. 二叉树主要通过链式储存，但如果是满二叉树和完全二叉树，也可以用数组顺序储存。
二叉树的特点: 1. 每个结点最多有两个孩子 2. 左、右孩子有区别 3. 每个结点可以有 0、1、2 个孩子  4.左子树和右子树本身也都是二叉树
## 使用顺序表完成二叉树操作
### 思考过程
本题采用顺序存储的方式表示二叉树。由于根结点存放在数组下标 `1` 的位置，因此对于下标为 `i` 的结点：
- 左孩子下标为 `2 * i`
- 右孩子下标为 `2 * i + 1`
1. 初始化时，将 `size` 设置为 `MAX_TREE_SIZE`，并把所有结点的 `used` 设置为 `false`，表示当前位置暂时没有结点。
2. 设置根结点时，直接在 `nodes[1]` 中存入数据并将 `used` 设为 `true`。
3. 设置左右孩子时，先判断父结点下标是否合法以及父结点是否存在，再计算孩子结点的下标，并判断是否越界。条件满足后，将数据存入对应位置并把 `used` 设置为 `true`。
4. 由于顺序存储的二叉树本身就是按照层次依次存放的，因此层序遍历时可以从数组下标 `1` 开始依次访问。对于未使用的位置输出 `-1`，并根据每层最后一个结点的下标 `2^n - 1` 判断何时换行。

**Q.为什么只用循环无法打印二叉树**
**A.链式二叉树中的结点不是像数组一样连续存储的，每个结点都有 `left` 和 `right` 两个分支，树的深度和结构也不固定，因此无法仅靠一个简单的 `for` 循环按下标依次访问所有结点。**
## 递归
以前序遍历为例，首先调用 `preorder(root)`，函数入栈，判断`root`节点不是空指针就先打印出`root`对应的值，然后递归调用`preoder(node1)`，`preorder(node1)`入栈后打印`node1`的值,然后递归调用`preoder(node3)`,`preoder(node3)`函数入栈后打印`node3`的值，由于`node3`的左右孩子均为空，因此分别调用`preorder(NULL)`后立即返回，随后`preorder(node3)`执行结束并出栈，程序返回`preorder(node1)`中继续执行。递归调用`preoder(node4)`，`preoder(node4)`入栈打印`node4`的值，由于`node4`的左右孩子均为空，因此分别调用`preorder(NULL)`后立即返回，随后`preorder(node4)`执行结束并出栈，至此,`node1`的左右子树都已遍历完成，因此`preorder(node1)`出栈。
随后程序返回到`preorder(root)`,然后递归调用`preoder(node2)`,`preoder(node2)`入栈后函数打印`node2`的值然后依次递归遍历`node5`和`node6`。当`node5、node6`的左右空孩子都处理完后，它们依次出栈，最终`preorder(node2)`也执行结束并出栈。最后回到`preorder(root)`，当左右子树均遍历完成后，`preorder(root)`出栈，整个前序遍历结束。
因此遍历顺序为root → node1 → node3 → node4 → node2 → node5 → node6
### `depth` 函数中为什么 `current_depth` 和 `max_depth` 不需要使用指针？
`int depth(TreeNode *root, int current_depth, int max_depth)`
其中 `root` 使用指针，是因为我们需要通过它访问当前结点以及它的左右子树。
而 `current_depth` 和 `max_depth` 只是用于记录深度的整数，不需要直接修改上一层递归中的变量，因此使用普通 `int` 即可。
递归调用时，每一层函数都会得到一份自己的`current_depth` 和 `max_depth` 
`current_depth` 在每一层分别保存当前结点的深度。当子函数结束后，会自动回到上一层原来的值，因此不需要通过指针手动修改。
`max_depth` 虽然也是值传递，但可以通过函数的返回值把子树中计算得到的最大深度传回上一层。
### 对递归和循环的理解
递归和循环本质上都有“重复执行某个过程”的特点。
循环通常通过 `for`、`while` 等语句控制重复次数和状态变化；递归则通过函数不断调用自身来完成重复过程，并利用函数调用栈保存每一层的状态。
对于二叉树这类具有递归结构的数据结构，递归会更加自然。例如遍历一棵树时，可以把问题拆成：
处理当前结点，处理左子树，处理右子树
而左子树和右子树本身又都是一棵二叉树，因此可以继续调用同一个函数。
循环通常执行效率更高，也不会产生大量函数调用；但如果使用循环遍历二叉树，往往还需要自己使用栈或队列保存后续需要访问的结点。
因此，我认为循环更适合结构比较简单、重复过程明确的问题，而递归更适合能够不断拆分成相同子问题的场景，例如二叉树遍历和回溯问题。
