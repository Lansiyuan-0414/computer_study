### 2.2没有乘法器的悲哀
由于该 CPU 没有硬件乘法器，直接使用 `*` 运算会调用库函数，耗时较长，因此需要使用移位和加减法代替乘法。
左移 `n` 位相当于乘以 `2^n`，因此可以将 29 拆分为：
29 = 32 - 2 - 1，即x × 29 = x × 32 - x × 2 - x
其中：
- `x × 32` 可以用 `x << 5` 表示
- `x × 2` 可以用 `x << 1` 表示
因此可以仅使用左移和减法完成计算，并减少运算次数。
**代码**
```c
# include<stdio.h>
int final_milk(int x) {
    int y;
    y = (x << 5) - ((x << 1) + x);
    return y;
}
 int main (void){
    int x;
    scanf("%d",&x); 
    int y = final_milk(x);
    printf("%d\n",y);
 }
```

### 3.2：补全浮点数对照表
A.非规格化 B.-6 C.$0.011_2=0.375$ D.$0.375*2^{-6}=3/512$ E.特殊值 F.2 G.$1.01_2=1.25$ H.$1.25*2^2=5$
### 3.3：阀门的极限
1. 最小正非规格化数：$0 0000 001_2=0.125*2^{-6}=1/512$,对应十进制值为 0.001953125 最大正非规格化数：$0 0000 111_2=0.875*2^{-6}=7/512$，对应十进制数0.013671875
2. 正最大规格化数：$0 1110 111=1.875*2^{7}=240$正最小规格化数：$0 0001 000_2=1*2^{-6}=1/64$对应十进制数为0.015625
3. 用 1-Bias 是为了让非规格化数和最小规格化数连续衔接，实现渐进下溢。

### 4.1:设计加法程序
###  设计加法程序
```c
# include <stdio.h>

int adder (int a,int b){
    int c = 0,sum = 0;
    int sign_a = a >> 7;
    int sign_b = b >> 7;
    int exponent_a = (a >> 3) & 0xf;
    int exponent_b = (b >> 3) & 0xf;
    int fraction_a = a & 0x7;
    int fraction_b = b & 0x7;
    if(sign_a == 1 || sign_b == 1){
    printf("暂时不支持负数运算\n");
    return 0;
    }
    if((exponent_a == 0 || exponent_a == 15)||(exponent_b == 0 || exponent_b >= 15)){
    printf("暂时不支持非规格数与特殊数运算\n");
    return 0;
    }
    int significand_a = fraction_a | 0x8;
    int significand_b = fraction_b | 0x8;
    if(exponent_a > exponent_b){//对阶
    c = exponent_a - exponent_b;
    exponent_b = exponent_a;
    significand_b >>= c;
    }
    if(exponent_a < exponent_b){
    c = exponent_b - exponent_a;
    exponent_a = exponent_b;
    significand_a >>= c;
    }
    sum = significand_a + significand_b;
    if (sum > 15){//规格化
        sum >>= 1;
        exponent_a++;
        if(exponent_a == 15){
            printf("超出运算上限");
            return 0;
        }
    }
    return  (exponent_a<<3) | (sum & 7);
}

int bi_to_int(const char a[]){//将输入的八位二进制数转化为真正的二进制数
```

### 4.2：老板为什么每天都在亏钱？
IEEE 754 浮点数的有效位数有限。当两个数量级相差很大的数相加时，较小的数在对阶过程中可能因尾数右移而被舍弃。因此不同的运算顺序会产生不同的中间舍入结果，使浮点加法不满足数学意义上的结合律。
对于算法1，先进行boss_wallet + daily_expense得出的结果是0.0再加一个15.0就没什么问题，但是对于算法二相比-1e20f来说，15.0f是个很小的数，在进行相加时经过对阶之后，15.0对应的尾数就会因为右移位数过多直接丢失了，最后直接就相当于1e20f-1e20f
